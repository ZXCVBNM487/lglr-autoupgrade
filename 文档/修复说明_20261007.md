# 修复说明与思路（2026-10-07）

本次对 lagrange_upgrade 项目做了一轮代码体检，共修复 3 个问题，1 项待用户补充信息。

## 已修复

### 1. config.json 的 adb_path 双重错误（最重要）
- **问题一**：填的是目录 `D:\FeverApps\MuMuFever\nx_device\12.0\shell\`，而代码用 `os.path.isfile()` 校验，目录永远校验不过。
- **问题二（更隐蔽）**：JSON 字符串里单反斜杠是转义符，`\n` 会被解析成换行、`\F`/`\1` 是非法转义，整个 config.json 解析直接抛异常，代码静默回退到全默认配置——意味着**之前配置文件里的所有自定义项（弹窗关键词、通知开关等）其实都没生效**。
- **修复**：改为合法 JSON 转义的完整文件路径 `D:\\FeverApps\\MuMuFever\\nx_device\\12.0\\shell\\adb.exe`（已验证该 adb.exe 真实存在）。
- **思路**：配置类问题要优先怀疑"解析是否成功"，静默回退默认值的容错设计会掩盖配置错误。

### 2. 截图降级方案残留临时文件
- **问题**：`exec-out screencap` 失败时走 `/sdcard/_lag_shot.png` + `adb pull` 的降级路径，用完后模拟器和本地各留一份临时文件，长期挂机越积越多。
- **修复**：改为 `try/finally` 结构，用完即删（模拟器侧 `rm -f`，本地 `os.remove`），且删除失败不影响主流程。

### 3. is_ready_button 冗余分支
- **问题**：第一个 `if t in READY_EXACT: return True` 与最后的 return 重复，属于无效代码。
- **修复**：简化为"先排除、再精确匹配"两行逻辑。行为完全等价（含排除关键词的文本不可能等于精确目标词），仅提升可读性。
