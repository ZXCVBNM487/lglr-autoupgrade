## 三、已发现并修正的问题

1. **奖励选择弹窗阻塞流程（严重）**
   - 现象：任务面板点「一键领取」后弹出「奖励选择」，需要玩家挑奖励；旧代码只找“确定/确认/关闭”，弹窗残留挡住全部后续导航。
   - 修正：`_daily_claim_tasks()` 与 `_daily_ensure_starmap()` 识别“奖励选择”，按设计坐标 `(1678,79)`（实机 `(1162,66)`@1600×900）点 X 关闭，不替用户选择奖励。
2. **任务面板关闭误命中（严重）**
   - 现象：旧 `icon_task_close.png` 命中右上展开/收起图标 `(1522,54)`，点完面板仍在，形成“关闭残留的任务面板”死循环。
   - 修正：`ICON_ONLY_ENTRIES.task_close` 停用该模板，改走展开/收起键设计坐标 `(2194,54)`（实机 `(1520,45)`）；`_TASK_CLOSE` 同步更新。
3. **坐标基准混用**
   - `points.json` 混淆“实机像素”和“设计基准”；`point_double_check()` 把实机像素当设计坐标再缩放，会点偏。
   - 修正：为 17 个点位补齐 `设计坐标`；函数优先读设计坐标，旧记录按 `分辨率` 换算；`points` 自检逐项校验两者一致性。
4. **活动 / 邮件 / 清单坐标错误**
   - 活动入口 `(150,43)`→`(150,46)`，设计 `(217,48)`→`(217,55)`；
   - 邮件 `(195,528)`→`(292,719)`，清单 `(143,528)`→`(212,716)`（旧坐标落在提示条上）。
5. **升级循环不唯一**
   - `_au_tap_upgrade()` 原有无视“只走一键升级”要求的普通升级兜底，已删除，找不到「一键升级」就不点。
6. **辅助输出与文档**

## 七、最终复核：点进基地建设 + 一键升级完整闭环（14:37–15:10）

### 7.1 本轮要解决的现象

用户明确要求「要点进基地建设，把代码改一下」。上一轮实测发现：脚本在基地建设
**3D 全景视图**里直接按设计坐标 `(1946,67)` 点「一键升级」，结果误开的是**分享面板**
（二维码 / 小红书）。根因是同一个屏幕位置在两种视图下是不同控件：

| 视图 | 右上 `(1345,50)` 附近 | 底部 | 「一键升级」按钮 |
|---|---|---|---|
| 3D 全景视图 | **分享图标** `(1345,50)` + 眼睛 `(1435,50)` | 「基地建设 1/2 / 中央区 / 港区 / 返回地图」+ 两条队列倒计时 | 无 |
| 建筑列表视图 | 「一键升级」文字按钮 `(1345,55)` + 折叠图标 `(1510,55)` | 建筑卡片等级（4/4、2/4…） | 有 |

也就是说：要「点一键升级」必须先在建筑列表视图；要「读两条队列倒计时」必须在
3D 全景视图。二者必须形成闭环，脚本才不会因读不到倒计时而反复点。

### 7.2 代码改动（均已写入 `lagrange_upgrade.py`）

1. **不再盲点坐标**：`cmd_autoup` 的基地页分支只有 OCR 明确读到「一键升级」文字才点；
   读不到且 `_au_base_list_view()` 判定为 3D 全景视图时，先点底部「基地建设」标签
   `(801,823)`@1600×900（设计 `(1156,988)`）展开建筑列表视图，等 5 秒转场后重新定位按钮。
   只有在列表视图内 OCR 漏读按钮文字时，才允许用已校准坐标 `(1946,67)` 兜底。
2. **分享面板兜底**：新增 `_AU_SHARE_PANEL_KEYS`（小红书等）识别 + 右上 X
   （实机 `(1520,45)` / 设计 `(2194,54)`）关闭，误开也不会卡死循环。
3. **视图判定**：新增 `_au_base_list_view()` —— 左上 y<0.2h 有「基地建设」标题
   且中部 0.4h~0.8h 有「中央区/港区/工业区」分区标题，才判定为建筑列表视图；
   3D 全景视图的这些文字全在底部 y>0.78h，不会误判。
4. **修资源误判**：面板左下「消耗资源」是「本次消耗 / 当前拥有」（`23.5万/106.4万` 表示充足），
   旧逻辑反着理解成「当前<需要」，还把面板里的升级耗时 `03:00:00` 当成攒够 ETA，
   导致点开面板后关掉、长等 3 小时、从不去点升级按钮。现删除该预判，
   直接点橙色「升级」按钮，资源够不够交给游戏判定（点击后有不足提示时再处理）。
5. **点完升级收起列表**：新增 `_au_back_to_panorama()`，点实机 `(1510,55)`
   （设计 `(2180,66)`）折叠图标回到 3D 全景视图，下一轮才能读到两条队列倒计时
   并静默等待；收起前先确认当前确实是列表视图，避免在全景视图误点分享区。

所有新坐标一律走 `scale_box()`，设计基准 2310×1080。

## 九、升级循环死循环修复：第一时间数升级数量（19:16–19:30）

### 9.1 现象与根因

用户给的截图（19:17）是基地 3D 全景视图，底部队列 **2/2**、两条倒计时
`02:00:40` / `00:33:42`。用户反馈升级循环变成死循环。

定位到根因（历史日志 `改码后实测_全景视图启动.log`）：

```
[14:59:57] 一键升级面板未打开，30 秒后复查（不进建筑详情）
[15:02:59] 一键升级面板未打开，30 秒后复查（不进建筑详情）
[15:03:52] 一键升级面板未打开，30 秒后复查（不进建筑详情）
```

脚本停在中间状态：**建筑列表视图底部是建筑卡片（4/4、2/4…），没有队列条**，
读不到"几个在升级" → 误判空位 → 去点一键升级又点不开 → 30 秒复查 → 无限空转。

### 9.2 修复

1. 新增 `_au_upgrade_state()`：第一时间数出 `(几个在升级, 倒计时列表, 是否读到可靠状态)`，
   读底部 `2/2 / 1/2 / 0/2` + 倒计时，区分"真 0 个"和"视图不对读不到"。
2. 循环开头：若 `readable=False` 且在建筑列表视图 → 先 `_au_back_to_panorama()` 收起回
   3D 全景重读，绝不把读不到当空位。
3. 按数量分流：**2 个** → 看倒计时、不管它、静默等待（+20 秒）；
   **1 个** → 看这一个还有多久、去点一次一键升级补位；**0 个** → 去点一次升级。
4. 点升级后面板没开：先关误弹面板、回全景视图重新计数，**删除原"30 秒复查"裸空转**。
